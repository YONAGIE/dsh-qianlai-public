# 钱来张姐 · 主体业务回归计划

本计划用于接手一份插件源码后，验证一家小规模服务企业能否从空环境开始，把一个月的材料整理成可交会计复核的账。覆盖财务工具、宿主批准、桌面附件和微信接续。工资覆盖计提和发放的账务处理。实际转账、税务网站登录与正式申报属于外部业务，本计划只验收插件可以提供的准备材料和操作边界。

## 准备和隔离

从仓库根目录运行，使用 Node.js 22.19 的 22.x 系列或 Node.js 24 及以上、仓库固定的 pnpm 版本。安装到 DSH 时选构建后的 `packages/dsh-qianlai` 子目录。使用[仓库合成素材](../../packages/dsh-qianlai/e2e/fixtures/README.md)。流水、税号、微信凭据和有身份信息的聊天记录均不作为 Issue 附件。

| 环境 | 何时换新的 DSH_HOME | 何时沿用 |
| --- | --- | --- |
| A 样本账、B 正常主流程 | A 和 B 各从全新目录启动 | B 从开账一直沿用到结账、导出 |
| C 错件与授权 | 每个会改变前置数据的反例用新目录，或从同一份已关闭的合成账本恢复 | 检查一次拒绝或重试前后沿用同一本账 |
| D 多月、E 跨年恢复 | D 和 E 分别建账 | 三个月连续做。跨年恢复时先关库，把合成账本副本放进新目录，再核对承接的余额 |
| F 微信绑定、G 渠道隔离 | 首次欢迎、需要首条消息、不同老板三个场景分别使用新目录 | 桌面与微信需要接续时，用同一宿主和同一目录。重启去重也沿用当前绑定 |
| H 真模型语言测试 | 每个独立剧本用新会话和新的测试输出目录 | 仅“上下文诱导后恢复”“更正前一条指令”等多轮用例沿用对话 |

通过标准同时看**用户看到的回复、实际调用的工具和账上落下的数据**。纯工具测试只证明后两项中的对应行为。判断拒绝、预演、重复点击等场景时，先记下凭证数、流水关联和金额，执行后再比一次。财务数字用原材料手算复核。

## 分阶段验收

| 顺序 | 业务场景与操作 | 核对点 |
| --- | --- | --- |
| P0·01 首次安装、查样本账 | 新目录装插件，选张姐，查样本 3 月报表、查不存在的月份，再尝试写入样本账 | 3 月末资产 485259.10 元，月利润 58754.60 元，年累计利润 183359.10 元。查不到的月份给原因，样本账不增加凭证 |
| P0·02 开账与期初 | 先取消、再同意用合成企业替换样本。分别给不平的期初、明确为零的期初、银行存款和实收资本各 1000 元的平衡期初 | 取消时保留样本。真账只建立一次，账名和开始月正确；未录期初与已确认为零可区分 |
| P0·03 收材料、核发票 | 依次提交正常票、错抬头、价税合计错、模糊和重复票。分别用进项票记销售、销项票记采购 | 核企业身份与票面金额。可读字段与待补字段分开，拒绝方向错误的预演和入账，重复票不形成第二张凭证。图片读数另走真模型验收 |
| P0·04 读附件、导流水 | CSV、XLS/XLSX、文字及混合 PDF 逐页或逐表核对，再导入。换损坏文件、余额不连续流水、编码不同的文本或同一份流水重试 | 示例工作簿读出 4 笔和期末 118890.00。读取与导入分两步。坏数据不部分写入，重复导入不增加行数，下一页不漏读，指令式摘要只作材料 |
| P0·05 记账、授权、对账 | 先预演，再测试取消、批准、重放同一调用。服务收入含税 101 元，净额 100 元、税额 1 元；银行手续费 10 元；分别在记账时和记账后关联流水 | 预演和拒绝时凭证数不变。实际批准后业务凭证两张，收入 100、费用 10、利润 90。银行流入流出分别与凭证相符，净额相同不能代替方向核对 |
| P0·06 更正和拒绝 | 未结月份作废后重记，已结月份冲销后更正；尝试重复冲销、挪用发票、零元记账、无原始垫付就还款 | 原凭证可追溯，已锁月份报表不变。拒绝后发票挂接、流水归属、凭证数和余额不变 |
| P0·07 结账与报表 | 先留一条未处理流水或缺失的公司事实，尝试结账；补齐后结账，再尝试补记；查询余额、损益、资产负债表并导出 | 缺件时提示具体阻断项。正常主流程结账后资产与负债及权益均为 1091.00，已结月拒绝写入。复核包八份文件，打开利润、凭证和流水文件交叉比对 |
| P0·08 季度和提醒 | 查截止日期及依据；同季录入以 1% 和 0.01 表示的销项票、真实零税额票、税额或不含税金额不可读的票。另查建账前与跨建账月的季度 | 税率正确归组，未知与零可区分。缺不含税金额时不给确定收入差额；缺税额时不连带抹去已知净额。显示实际覆盖期、未入账票及未结月，准备单不触发税务提交 |
| P1·09 工资、资金与往来 | 股东实缴 10000 元，一月计提工资 2000 元，二月发 1750 元并代扣 150、20、80 元；另测员工垫付与后续归还 | 实缴增加权益，发薪后银行 8250 元，工资应付清零，三项代扣仍可查。二月无重复工资费用，年累计工资费用 2000 元。完整垫付款核销待补齐逐笔来源 |
| P1·10 连续使用与恢复 | 连做三个月，另建账从十二月做到次年。关库后复制账本恢复到新目录，再查询和追加业务 | 收支、锁月、凭证编号和上月余额能承接；新年度利润只累计新年度。核对恢复前后同一报表和导出清单 |
| P1·11 桌面和微信接续 | 桌面请求登录码、刷新过期码、已连接时再次询问。新绑定核查欢迎、使用说明、备注与头像引导、三张图片；已有桌面财务任务时验证接续。模拟需要首条消息、网络断开、退出重启、他人确认 | 只有已绑定老板的有效确认能触发一次写账。同一任务不会因重启被重复入账，欢迎不重发。普通轮询不编造新任务。真人扫码、微信首屏送达和保存头像分别记录 |
| P1·12 语言、角色与越权 | 真模型分别测试“一月/下月”、省略年份、口语金额、付款方式含糊、撤回确认、重复提问、角色诱导，以及材料内伪指令。先在新会话测，再带旧会话上下文复测 | 歧义时先确认，不自行开账或写账；金额能回溯到工具。允许与账务有关的主动提醒、邀约。异常保留脱敏输入、可见回复、工具名和账面差异，并记录复现次数 |

对 P0·06 单独运行 `pnpm --filter dsh-qianlai exec vitest run tests/reversal-intent.spec.ts`。把已结月份的合成误记先在开放月冲销。分别选整笔撤销和指定未来月份补记。核对原月凭证、补记月的结账阻断、预演、正式更正、作废后再次阻断，以及复核包上的原凭证号。旧账没有冲销用途记录时保留原流程。

## 运行顺序

### 1. 每次改动可自动复跑

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm typecheck
pnpm lint
pnpm test
node packages/dsh-qianlai/e2e/check-accounting-flow.mjs
node --test packages/dsh-qianlai/tests/wechat-runtime.test.mjs
node packages/dsh-qianlai/e2e/q008/run.mjs --validate
pnpm pack:all
pnpm test:packages
```

[记账主流程](../../packages/dsh-qianlai/e2e/check-accounting-flow.mjs)调用构建产物实际注册的工具，以独立合成账本和模拟的一次性宿主批准运行。成功时打印凭证数、利润、资产、锁月和导出数量。针对单组功能可从根目录运行 `pnpm --filter dsh-qianlai exec vitest run tests/year-change-restore.spec.ts`；将文件名替换为 `payroll-flow.spec.ts`、`statement-links.spec.ts`、`uploads.spec.ts`、`assist.spec.ts` 或 `quarter-book-period.spec.ts` 可复验相应业务。Q-008 的 `--validate` 只校验材料。

### 2. 使用有额度的测试模型

按[真模型环境说明](../../README.zh.md#微信与真模型测试)在独立环境设置 `DEEPSEEK_API_KEY`、`DSH_ENTRY` 和需要时的 `ZSTD_BIN`。每次使用新的 `E2E_OUT`，先运行 `node packages/dsh-qianlai/e2e/run.mjs --list` 选择场景。示例分开运行：

- 金额与附件：`node packages/dsh-qianlai/e2e/run.mjs invoice-preview-then-record statement-xlsx statement-pdf-mixed statement-injection`。无人值守的合成账本写入场景显式采用 `E2E_APPROVAL_MODE=allow`。另以 `reject` 运行 `native-approval-rejection` 验证拒绝路径。
- 月份和角色：`node packages/dsh-qianlai/e2e/run.mjs issues-month issues-persona persona-`。诱导与正常业务分别统计，建议用 `E2E_REPEAT=3` 重复同一批输入，人工复核逐轮回复。
- 微信：运行 `node packages/dsh-qianlai/e2e/run.mjs wechat-qr-`、`node packages/dsh-qianlai/e2e/check-wechat-onboarding.mjs`、`node packages/dsh-qianlai/e2e/check-wechat-approval.mjs`。微信专用批准场景使用自己的合成收发链，不启用全局自动批准。

### 3. 真人验收

在单独测试绑定上，分别用手机微信和电脑微信测试扫码、无需首条消息能否送达、首条消息后的续发，以及长按保存三张素材。先在桌面讨论一项未完成的合成财务任务，核对主动消息提到的工作和账本进度，重启再看是否重复。以实际收到消息、看到的账本状态为准。做 Windows、macOS、Linux 版本验收时，分别记录系统、Node、DSH、依赖安装和上述命令的结果。
